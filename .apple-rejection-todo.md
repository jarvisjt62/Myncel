# Apple App Store Rejection — Submission 1e279a14 — Fix Plan

## Apple's findings (reviewer: iPad Air 11-inch M3, iPadOS 26.5, May 21 2026)

1. **3.1.1 IAP** — "App includes account registration for businesses/orgs → external purchase mechanism → remove."
2. **2.1 Information Needed** — Demo creds `googleplay@myncel.com` / `Google123456!` did not work.
3. **2.1(a) App Completeness** — "Continue button greyed out during registration."

## Investigation (already done)

- iOS app (`myncel-mobile/`) has **no registration UI** — only Sign In + Forgot-password (which redirects to web).
- The bug must be in **web `/signup`** (which the reviewer reached after demo creds failed).
- Web `/signup` has Step 1 "Continue" button disabled by `!passwordMeetsRequirements || passwords don't match`.
  - Likely iPad failure: iCloud Keychain autofills `password` field but not `confirmPassword`, OR React state misses autofill events → button stays disabled.

## Fix plan

### A. Web `/signup` — fix the iPad "Continue greyed out" bug
- [ ] Add `autoComplete`, `autoCapitalize="off"`, `autoCorrect="off"`, `spellCheck={false}` to password fields
- [ ] Add `onInput` fallback handlers (catch autofill that React's `onChange` misses)
- [ ] Make button enabled at all times — validate on click and show specific error
- [ ] Show *why* it's disabled (live hint: "Confirm password must match", etc.)
- [ ] Test by typecheck + visual inspection

### B. Mobile iOS app — remove ALL hints of business registration
- [ ] Audit `LoginScreen.tsx` for any "Sign up" / "Create account" / "Free trial" affordance — none found, confirmed
- [ ] Make sure "Forgot password" alert doesn't say "visit myncel.com to register" — it currently says "reset your password from the Myncel website" which is fine
- [ ] Update copy on Login screen to be 100% clear: "Sign in with credentials provided by your workspace admin."
- [ ] Add a "How do I get an account?" helper text → modal saying "Myncel accounts are created by your organization's admin on myncel.com. Ask your admin to invite you."

### C. Demo account — create fresh working credentials for Apple
- [ ] Build seed script `scripts/seed-apple-review-account.ts` that:
  - Deletes any existing `appstore-review@myncel.com` user
  - Creates org "Apple Review Demo"
  - Creates user `appstore-review@myncel.com` with strong password, email pre-verified, role ADMIN
  - Seeds 5 sample equipment, 3 work orders, 2 schedules, 2 alerts so the app isn't empty
  - Also fixes `googleplay@myncel.com` (the existing one) so old credentials work too as a fallback
- [ ] Run script against production DB
- [ ] Verify by signing in via web AND mobile

### D. App Store Connect response
- [ ] Draft a clear, structured reply to Apple Review
  - Acknowledge each finding by guideline number
  - Explain: iOS app is sign-in only (no registration); registration is done by org admin via myncel.com (not in-app)
  - Provide new working demo credentials
  - Document the Continue-button fix (commit hash, deployed timestamp)
- [ ] Save reply text to `docs/apple-review-response-2026-05-22.md` for user to paste into App Store Connect

### E. Verify, commit, push, ship a new TestFlight build
- [ ] `npx tsc --noEmit` (web)
- [ ] In `myncel-mobile/`: `npx tsc --noEmit`
- [ ] Commit web fixes
- [ ] Commit mobile copy changes
- [ ] Bump iOS build number 11 → 12 in `app.json`
- [ ] Push to main
- [ ] User then runs EAS build (or GitHub Action) to produce 1.0 (12) for resubmission
